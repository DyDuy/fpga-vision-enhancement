# Bảng chức năng kiến trúc thư mục đến cấp sâu nhất

Đọc bảng này để biết **code ở đâu, tool sinh gì và dữ liệu nào cần giữ**. Bảng dễ đọc gom các cây run/cache lặp lại; [directory-inventory.csv](directory-inventory.csv) liệt kê **mọi thư mục được duyệt tới lá** dưới đúng phạm vi trong [metadata, `rules`](directory-inventory-metadata.json). Việc kiểm kê chỉ đọc tên/metadata tệp, không chạy tool và không xác minh thuật toán hay hoạt động board.

### Ba loại file phải phân biệt

1. **Nguồn chuẩn để chỉnh:** các `.qsys` trực tiếp trong `hardware/qsys/`; RTL/IP descriptor/ROM trong `hardware/de1_soc/`; pin/SDC trong `hardware/pin/`.
2. **File sinh tự động, không sửa trực tiếp:** `hardware/qsys/<system>/synthesis/`, `simulation/`, `submodules/`, `.qip`, `.sopcinfo`, generated SDC và output trong run. Nếu thấy `dehazing_system_top.v` trong `submodules/`, đó không phải nơi sửa IP gốc. Với IP vendor, sửa tham số trong Qsys/IP editor; không vá HDL vendor đã sinh.
3. **Snapshot và bằng chứng:** `hardware/archive/`, verification intake, report/bitstream/log trong `build/`. Không dùng chúng làm nguồn active hoặc xóa hàng loạt chỉ vì bị Git ignore. Nếu cần sửa constraint do generator/vendor tạo, tìm cấu hình/nguồn tạo constraint trước; không sửa generated SDC như nguồn lâu dài.

### Chu trình chỉnh sửa → build

```text
Nguồn: de1_soc/ + pin/ + qsys/
                  |
                  v
build_fpga.py: stage (copy input, hash, điều chỉnh đường dẫn)
                  |
                  v
build/quartus/vision_1x1/runs/<run-id>/
                  |
                  v
VGA_Subsystem → Video_In_Subsystem → Computer_System (Qsys generation)
                  |
                  v
Quartus compile → report/bitstream/log của run
```

Chạy từ root repo:

```bash
python software/python/check_project.py
python software/python/build_fpga.py stage       # chỉ kiểm tra/sao chép input
python software/python/build_fpga.py generate    # run mới: stage + generate Qsys
python software/python/build_fpga.py compile     # run mới: stage + generate + compile
```

Không bắt buộc chạy cả ba lệnh build liên tiếp: `compile` đã bao gồm stage/generate. Mỗi lệnh tạo run riêng, không tiếp tục chỉnh một run cũ. Cần cấu hình môi trường Quartus theo [automatic-build](automatic-build.md). Checker không chứng minh RTL, timing hoặc board đúng.

**Khi dùng GUI:** mở đúng `.qsys` nguồn tương ứng, cấu hình đường tìm custom IP đến `hardware/de1_soc/` nếu Catalog chưa thấy component, kiểm tra tên/version rồi lưu. Không dùng `.qsys` dưới `build/` để sửa lâu dài vì đó là bản sao của một run. QSF nguồn đã tham chiếu `../pin/` và `../qsys/`; nếu compile trực tiếp từ GUI, generated QIP phải tồn tại đúng đường dẫn đó. Build automation dùng bản stage riêng, không dựa vào generated folder cũ cạnh source.

**Ví dụ:** muốn đổi phép tính transmission → sửa `hardware/de1_soc/dehazing_system_top.v` (và LUT nếu cần) → mô phỏng RTL active → chạy `compile`. Muốn đổi cổng stream của IP → sửa RTL + `_hw.tcl` → cập nhật kết nối trong `.qsys` và wrapper nếu bị ảnh hưởng → generate/mô phỏng/compile. Muốn đổi chân VGA → sửa pin QSF và kiểm tra top-level port, không sửa Qsys generated HDL.

## D — Cách dùng, tái lập và giới hạn

1. **Sửa hardware hiện hành:** RTL/QPF/QSF/IP Tcl/ROM trong `hardware/de1_soc/`; pin/SDC trong `hardware/pin/`; ba Qsys trong `hardware/qsys/`. Sau thay đổi cần generate/compile lại. [Nguồn: hardware README:14](../../hardware/README.md#L14), [pin README:3](../../hardware/pin/README.md#L3), [Qsys README:18](../../hardware/qsys/README.md#L18).
2. **Sửa software:** C tại `software/hps/src/`, header tại `include/`; tool build/check/image/bug journal tại `software/python/`; MATLAB tại `software/matlab/` có trạng thái prototype. [Nguồn: HPS README:35](../../software/hps/README.md#L35), [README:45](../../software/hps/README.md#L45), [Python README:7](../../software/python/README.md#L7), [Software README:21](../../software/README.md#L21).
3. **Sinh RTL bằng tool:** viết đầu vào trong `hardware/generation/src/<tool>/`, đặc tả trong `specs/`; config/adapter còn cần triển khai. Không chỉnh generated Verilog trong run để thay đặc tả. [Nguồn: generation README:57](../../hardware/generation/README.md#L57), [README:60](../../hardware/generation/README.md#L60), [README:72](../../hardware/generation/README.md#L72).
4. **Ghi khắc phục:** mở `build/bug/<domain>/<incident-id>/journal.md` của sự cố nếu có; ghi triệu chứng, giả thuyết/nguyên nhân, tệp/commit sửa và run/log kiểm chứng. Đổi Markdown không tự cập nhật record JSON. [Nguồn: bug-logging:28](bug-logging.md#L28), [bug-logging:74](bug-logging.md#L74).
5. **Xem sâu nhất:** mở CSV trong VS Code hoặc Excel bằng UTF-8; lọc `is_leaf=true` hoặc sắp xếp `depth` giảm dần, lọc prefix `relative_path` để xem mọi nhánh. Các số liệu trong guide đến từ cùng CSV/metadata snapshot, không là benchmark hiệu năng. [Nguồn: metadata, `counts`, `csv`](directory-inventory-metadata.json).

Generator một lần được giữ cục bộ trong vùng Git ignored. Tái tạo từ root (ghi đè **ba đầu ra tài liệu**, không chạy build/tool hay sửa nguồn thiết kế):

```powershell
python build/documentation/directory-inventory/generate_directory_inventory.py
```

Script này không phải entrypoint production, không theo link/reparse chuyển hướng; cloud placeholder chỉ đọc metadata, không đọc payload source/binary/VCD khi đếm. Chỉ đọc lại CSV vừa sinh để tính SHA256 của **artifact kiểm kê**, không hash nội dung tệp dự án. Nếu metadata không đọc được, JSON ghi `errors` và `complete_under_declared_rules=false`; nếu có liên kết/tệp đặc biệt, JSON ghi `skipped_links_or_nonregular_entries`. [Nguồn: metadata, `generator`, `rules`, `csv`, `errors`](directory-inventory-metadata.json). Generator nằm trong `build/`, có thể không có ở checkout khác; ba artifact có phiên bản vẫn giữ snapshot đã tạo. Tái chạy thay số đếm và locator dòng theo cây hiện tại.

Các dẫn nguồn `#L<n>` chỉ đúng tại phiên bản tệp được đọc ở lần viết guide này; tên trường JSON và `relative_path` CSV là điểm đối chiếu bền hơn khi tái tạo. Role/hướng dẫn được suy luận từ source/README hiện hành và tên tệp như ghi trong `evidence`, không phải phân tích nội dung mọi tệp. Không đo throughput, timing, chất lượng ảnh, tài nguyên hay hoạt động board ở bước lập bảng.
